# F01 Dispatcher

Reconstruct as scheduled flow owned by AutomationUPN with OwnerUPN co-owner. This is the sole business writer. Approval waits run only in F02. Native actions and stable bindings follow [shared rules](README.md) and [expressions](expressions.md). Place each loop body in `Try_command` Scope and `Catch_command` Scope; Catch runs after Try failed/timed out. Each rejection is an explicit branch, so one bad command cannot terminate the batch. Native Terminate is used only outside loops; inside a loop use branch completion.

Initialize the documented variables before For_each_command because Power Automate cannot initialize variables inside loops. Clear them at the start of every iteration. Set_variable actions listed as an expansion receive names `Set_<VariableName>`; per-case Compose/Set actions receive `Plan_<CommandType>` and `Set_plan_<CommandType>`. Store an object Plan with typed values, not expression strings.

## Exact transition and field plan

Each case checks its listed source, role and required fields in [the process contract](../contracts/process.json). No implied transitions exist. All accepted transitions increment Revision once and set LastCommandKey. ExpectedRevision equals current Revision except Submit; decisions/expiry also equal ApprovalJobs.RequestedRevision. Human role values come only from Actor_roles.

| Command | Exact source → destination / role | Guards and Plan fields |
|---|---|---|
| Submit | no existing order → Submitted / Sales | Validate Title, CustomerCode, ProductType, Quantity, DueAt > command Created. Derive SalesUPN=ActorUPN, SubmittedAt=TransitionAt; initial Revision=1. Ignore supplied OrderKey, actor/role and output fields. |
| Validate | Submitted → AwaitingApproval / Prepress | QuoteEUR positive/2 decimals, consent and signed PreflightChecklistRef nonempty; exact single allowed ApproverUPN with Approver role; valid PDF <=20 MB. ApprovalKey=OrderKey-rNewRevision. Copy immutable snapshot before mutation. Set QuoteEUR, DraftFilePath, CustomerConsentRef, ApproverUPN, ApprovalKey, ApprovalSnapshotPath, ApprovalRequestedAt=TransitionAt, ApprovalDueAt=TransitionAt+72h. Clear ReleasedFilePath and prior approval/production/completion timestamps only in this new cycle. Checklist persists in trusted receipt/command. |
| RequestChanges | Submitted → ChangesRequested / Prepress | Nonempty Reason. Preserve business fields; receipt records reason. |
| Resubmit | ChangesRequested or ApprovalExpired → Submitted / Sales | Updated Title, CustomerCode, ProductType, Quantity, DueAt > TransitionAt and correction Reason. Preserve immutable SubmittedAt and original SalesUPN. Clear current ApprovalKey, ApprovalSnapshotPath, ReleasedFilePath, ApprovalRequestedAt/ApprovalDueAt/ApprovedAt so old jobs cannot authorize the new cycle; retain old jobs/events/files as audit evidence. |
| ApprovalApproved | AwaitingApproval → Approved / Automation | Service Author plus Automation mapping; exact one job with matching current key, revision, assigned responder and snapshot. Require job response metadata written by F02; compare command ResponseUPN/ResponseAt to that evidence and Outcome=Approve. ResponseAt <= DeadlineUtc, including processing after deadline. Set ApprovedAt=ResponseAt, preserve ApprovalKey and snapshot. |
| ApprovalRejected | AwaitingApproval → ChangesRequested / Automation | Same decision guard, Outcome=Reject, nonempty Reason from approval comments or literal `Internal approver rejected without comments`. No success default for missing outcome. Preserve audit key/snapshot until Resubmit. |
| ApprovalExpired | AwaitingApproval → ApprovalExpired / Automation | Service Author, Automation mapping, matching key/revision/job deadline and TransitionAt >= DeadlineUtc. Before commit inspect persisted job response and queued decision commands. A timely persisted decision or racing decision queue causes NeedsReview/ApprovalQueueRace, not automatic expiry. Owner resolves queue ordering using observed records. No automatic revival after an expiry already applied. |
| Release | Approved → ReadyForProduction / Prepress | Verify current approved job, approval event, trusted snapshot identity and existing immutable PDF. Copy snapshot before state mutation, not draft. Set ReleasedFilePath to ProductionFiles/{ApprovalKey}-approved.pdf. If ApprovalKey is PO-000001-r2 and current Approved Revision=3, released file remains PO-000001-r2-approved.pdf. |
| StartProduction | ReadyForProduction → InProduction / Production | ProductionUPN exactly one configured Production identity; released metadata exists and matches trusted release receipt. Set ProductionUPN, ProductionStartedAt=TransitionAt. |
| Complete | InProduction → Completed / Production | Nonempty signed QCReference, manual QC passed, integer WasteQuantity in [0,Quantity]. Set QCReference, WasteQuantity, CompletedAt=TransitionAt. Failed QC stays InProduction for manual rework. |
| Cancel | Submitted, ChangesRequested, ApprovalExpired, Approved or ReadyForProduction → Cancelled / Sales or Owner | Reason nonempty; ProductionStartedAt absent. Set CancelledAt=TransitionAt. AwaitingApproval, InProduction, Completed and Cancelled reject. |

Native `Build_plan` Switch has exactly these 11 cases. Each case's Compose constructs a JSON object whose properties are the schema names in the table. Default goes to Reject_command/UnknownCommand. Do not build conditional expressions that evaluate absent dates or arrays before the relevant command branch.

## Deterministic effects

`Ensure_event`: Title=EventKey; EventKey=OrderKey-rNewRevision; OrderKey; CommandID=Command.ID; FromStatus=null for Submit else previous Status; ToStatus=Plan.Status; Revision=NewRevision; EventAt=TransitionAt; ActorUPN=immutable author; Role=the matching transition role (use Owner for Cancel only when Sales is absent); EventType=CommandType; ApprovalKey=current cycle key when applicable; DurationHours=null unless a measured duration has a defined start (for decisions/expiry, elapsed hours since ApprovalRequestedAt). Never store fake zeros for unknown durations.

`Ensure_job` at Validate: Title/ApprovalKey=the new key; OrderKey; RequestedRevision=NewRevision; AssignedUPN=validated ApproverUPN; DeadlineUtc=ApprovalDueAt; JobState=New; ApprovalId/StartedAt/FinishedAt/Outcome/ResponseUPN/ResponseAt/ErrorDetail=null; SnapshotDraftPath=DraftFilePath; ApprovalSnapshotPath=immutable destination; SnapshotQuoteEUR=QuoteEUR. Author must be AutomationUPN. Create only after order commit; repair a missing job from receipt. F02 checks that exact committed order.

`Ensure_outbox`: two deterministic rows per notified transition, MessageKey=EventKey-Email or EventKey-Teams; Title=MessageKey; OrderKey; Channel; Recipient=SalesUPN for normal Email transitions and OwnerUPN for ApprovalExpired/incidents; Teams Recipient=ChannelId, with TeamId taken from config. TemplateKey: Submit→submitted; RequestChanges/ApprovalRejected→changes-requested; ApprovalApproved→approved; Release→ready; Complete→completed; Cancel→cancelled; ApprovalExpired→approval-expired. Validate/Resubmit/StartProduction do not create routine notifications. SafePayload is a trusted JSON string containing only OrderKey, Status and the same-site Orders item link; no artwork/customer data. DeliveryState=Pending, AttemptCount=0. Recipe conditions skip Ensure_outbox entirely when no template applies. Messages can remain Pending while notifications are disabled.

## Partial-write recovery

No automatic replay after Claim_command. Any error after claim retains the receipt and becomes NeedsReview. If a crash leaves Processing, F04 flags it after 15 minutes. Owner pauses F01 for this repair, proves automation authored the receipt using version history, and checks Orders.LastCommandKey/Revision. If they equal CommandKey/NewRevision and every Plan field agrees, Owner completes only missing deterministic event/job/outbox rows, compares existing payloads, and marks Applied. If the order still equals FromStatus/OldRevision and no order mutation occurred, inspect every file/approval side effect before resetting Pending. A trusted matching file receipt can support repair; uncertain copy without identity requires manual verification or a fresh revised command after quarantining the unused file. Never delete or overwrite approved/released files to hide uncertainty. An order with a different LastCommandKey or revision requires incident review; do not overwrite newer state.

Malformed human PayloadJson, LastCommandKey, AppliedRevision, ProcessingStartedAt or caller-supplied role never enters an authorization guard. Incoming PayloadJson cannot supply a recovery receipt. Submit derives identity even when the caller supplied another OrderKey. Owner recovery must check list history, Editor=automation for the receipt version, and absence of later tampering. This gate prevents forged receipts from skipping validation.

## File action gate

The current [SharePoint connector reference](https://learn.microsoft.com/en-us/connectors/sharepointonline/) exposes Destination Folder on modern Copy file, so it cannot be assumed to rename an arbitrary draft. This reconstruction explicitly uses **Copy file (deprecated)** (operation CopyFile) for its documented Destination File Path and Overwrite Flag=false inputs. The tenant must prove availability, same-site deterministic naming and failure without overwrite. If the operation is unavailable, activation blocks until Owner approves and verifies a native SharePoint REST CopyTo replacement with overwrite=false. Do not silently substitute Create file or modern Copy file. Metadata 404 during pre-effect file validation rejects InvalidFile; permissions/throttling/service errors route NeedsReview. Unknown copy outcomes always require Owner reconciliation.
