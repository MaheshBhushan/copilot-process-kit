# Native flow reconstruction

These specifications describe four Power Automate cloud flows. They are designer reconstruction instructions, not importable exports. No tenant flow, connector binding, approval, message or permission has been created or tested.

Build [F01](F01-dispatcher.md), [F02](F02-approval-worker.md), [F03](F03-notification-worker.md) and [F04](F04-watchdog.md) disabled. Use [expressions](expressions.md), [action map](action-map.csv), [process contract](../contracts/process.json), [schema](../contracts/sharepoint-schema.json) and [runbook](../deployment/runbook.md). Preserve action names exactly. Each table row represents one native action; place each action in the indicated branch or scope. Loop bodies use sequential execution unless stated otherwise. Action-map IDs identify table rows across flows.

All connections belong to configured AutomationUPN. OwnerUPN is a named recovery co-owner. F01 alone writes Orders. All flows check EnableAutomation before work; F03 also checks EnableNotifications. Configuration values come from environment variables in the solution or explicit per-flow Compose inputs in the manual path. Config is loaded once per run. Changes affect new runs; disable and inspect active runs before pausing side effects.

Table shorthand: `S` = run after preceding action succeeds in the same branch; `F/T` = configured run after failed or timed out; `N` = retry policy None; `R` = exponential, count 4, interval PT5S, maximum PT1M, with connector throttling honored. Reads use R. Unique creates, file copies, approvals, sends and posts use N. A failed unique create is reconciled by a GET and full payload comparison; a conflict alone never proves success. A conditional MERGE with uncertain outcome requires reread and receipt comparison; never blindly replay a mutation. Use explicit success/failure branches so a handled 412 does not fall into generic recovery.

The pilot ceiling is 1,000 rows per indexed watch query, 25 command/outbox rows per batch, one dispatcher, and 20 concurrent approval runs. Get items pagination is On with threshold 1,000 for watch and same-order barrier queries, and Off for top-25 polling. Query equality uses indexed state/key columns. Validate query plans and backlog age in the tenant; hitting 1,000, list-threshold errors, or sustained backlog blocks expansion. Scale requires tenant-specific query partitions and a reviewed throughput plan.

SharePoint has no transaction across lists. A transition receipt, unique keys and an order barrier support manual repair. They do not provide exactly-once approvals, files or delivery. [Recovery and evidence](../deployment/evidence-template.md) must be completed before enabling the pilot.

Action-map `ActionId` is `<Flow>_<ActionName>` and is globally unique; `ActionName` is the actual designer name used in expressions. `ContractRefs` uses semicolon-separated `List.InternalName` paths; ID, Author, Editor, Created and Modified are SharePoint built-ins. `BPMNRefs` uses semicolon-separated exact BPMN XML IDs. Scope/loop rows explicitly enumerate native child expansions in their inputs; save those generated child names in the tenant inventory before enablement.
